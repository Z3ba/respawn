# 1. Namena i koncept aplikacije

## 1.1. Namena i domenska oblast

Respawn je mobilna aplikacija namenjena jednoj prodavnici gaming opreme. Domenska oblast obuhvata prodaju tastatura, miševa, slušalica i podloga. Aplikacija treba da objedini pregled ponude, informacije o proizvodima i proces poručivanja putem mobilnog uređaja.

## 1.2. Opis problema i motivacija

Pri kupovini periferija korisniku su potrebne pregledne informacije o karakteristikama, ceni i dostupnosti. Izbor otežavaju neujednačeni opisi i ponuda u kojoj se teško pronalazi odgovarajuća oprema. Respawn će organizovati proizvode po kategorijama i omogućiti pretragu i filtriranje, kako bi korisnik lakše pronašao proizvod koji odgovara njegovim potrebama.

## 1.3. Ciljna grupa i ciljevi korisnika

Aplikacija je namenjena igračima i korisnicima računara koji kupuju periferije za igranje, rad i svakodnevnu upotrebu. Administratori prodavnice predstavljaju drugu grupu korisnika, zaduženu za održavanje ponude i obradu porudžbina.

- Pronaći proizvod prema nazivu, kategoriji, brendu ili ceni.
- Pregledati karakteristike, fotografije, cenu i dostupnost proizvoda.
- Sačuvati omiljenu opremu i upravljati korpom.
- Poručiti proizvode i pratiti status prethodnih porudžbina.

## 1.4. Uloge i ključne planirane funkcionalnosti

Gost će moći da pregleda i pretražuje ponudu. Registrovani kupac će, nakon prijave, koristiti omiljene proizvode, korpu, poručivanje, istoriju porudžbina i svoj profil. Administrator će upravljati proizvodima, kategorijama, korisnicima i porudžbinama kroz zaštićenu sekciju aplikacije.

Planirane funkcionalnosti obuhvataju katalog, detalje proizvoda, pretragu i filtere, registraciju i prijavu, omiljeno, korpu i porudžbine. Plaćanje će biti omogućeno pouzećem i karticom preko Stripe-a u test režimu, bez stvarne naplate tokom demonstracije projekta.

# 2. Izbor tehnologija

## 2.1. Mobilna aplikacija

Flutter i programski jezik Dart izabrani su za izradu aplikacije. Flutter omogućava sastavljanje interfejsa od widget-a, doslednu temu i razvoj više ekrana iz jedne baze koda. Android je prva ciljna platforma, dok web verzija služi kao pomoćni pregled tokom razvoja.

Provider i ChangeNotifier koriste se za izdvajanje stanja iz korisničkog interfejsa. U početnoj aplikaciji upravljaju temom i stanjem početnog kataloga. SharedPreferences čuva izbor svetle ili tamne teme između pokretanja aplikacije. Material Design predstavlja osnovu vizuelnih komponenti.

## 2.2. Backend, baza i integracije

| Tehnologija | Namena | Stanje u KT1 |
| --- | --- | --- |
| Node.js i Express | HTTP servis i buduća serverska logika | Osnova servisa i GET /health |
| Firebase Authentication | Registracija, prijava i identitet korisnika | Planirano |
| Cloud Firestore | Čuvanje korisnika, proizvoda i porudžbina | Planirano |
| Firebase Admin SDK | Serverska provera identiteta i privilegovane operacije | Planirano |
| Stripe i flutter_stripe | Kartično plaćanje u test režimu | Planirano |

Kod kartičnog plaćanja server će proveravati proizvode i izračunavati iznos na osnovu baze. Mobilni deo će prikazivati Stripe PaymentSheet, a serverska potvrda plaćanja obrađivaće se putem webhook-a. Ova integracija još nije implementirana u KT1.

## 2.3. Okruženje i razvojni alati

Razvojno okruženje je Windows, sa Flutter 3.47.9, Dart 3.13.7, Node.js 24.14.1 i punim JDK 21. Za Android build pripremljeni su Android SDK i build alati. Razrešene verzije paketa čuvaju se u pubspec.lock i package-lock.json fajlovima.

Na vežbama su prikazani Dart, Flutter, Android Studio, AVD emulator i VS Code sa Dart i Flutter ekstenzijama (slajdovi 2-11). VS Code je predviđen za uređivanje koda, a Android Studio za rad sa emulatorom. Postojeći build izvršen je komandnim SDK alatima; instalacija IDE-a i ekstenzija nije proverena. Dart SDK već postoji u lokalnoj Flutter instalaciji.

Na slajdu 13 paketi http i provider navedeni su kao primeri dependencies, a oba već postoje u našem projektu. Prezentacija ne propisuje paket za bazu, autentikaciju ili plaćanje. Firebase, Node.js/Express i Stripe su izbor projekta Respawn. Git i GitHub služe za verzionisanje i deljenje koda; lokalni prototip za prikaz dizajna.

Napravljen je Android paket rs.respawn.respawn, verzija 0.1.0, sa minimalnim API nivoom 24 i ciljnim nivoom 36. APK sadrži podršku za armeabi-v7a, arm64-v8a i x86_64 arhitekture.

Test emulator nije postao dostupan u ovom okruženju. Virtualizacija je isključena u firmware-u računara, a pokušaji softverskog rada nisu omogućili završnu proveru pokretanja. Tu proveru treba izvršiti na fizičkom telefonu ili posle podešavanja emulatora. Uspešan build se zato ne predstavlja kao potvrđeno pokretanje aplikacije.
